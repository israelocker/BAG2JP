# BAG1 → BAG2 Character Import: Standard Task Guide

## Quick Summary
Import a BAG1 character (e.g., Heat) into BAG2JP using the canonical runbook. This guide provides the essential steps, evidence requirements, and acceptance criteria.

**Duration:** depends on unresolved format/semantic issues; no verified fixed estimate.
**Dependencies:** CHARACTER_IMPORT.md, NOTES.md, _work/current-state.json, tools/bag1import/

**Reusable recipes:** `notes/character-alternate-entries.md` (member rebuild,
exact payloads, preservation and staging) and `notes/character-import-testing.md`
(calibration, full matches, side/costume matrix and diagnosis). Read only the
relevant phase. Strike evidence is in `notes/strike-recovery.md`, not a universal
source of IDs, patches or animation mappings.

## 2. Import Workflow (Step-by-Step)

### Step 1: Initialize Profile
```bash
# Verify the character has a profile in CHARACTER_IMPORT.md
# Check: Does this character have a documented import path?

# Run compact status to see current state
py -3.13 tools/bag1import/character_workflow.py status --profile tools/bag1import/profiles/<slug>.json
# Review _work/current-state.json
```

### Step 2: Inspect the Plan
Review `CHARACTER_IMPORT.md` section 2 ("Non-negotiable rules") and section 5 ("Profile schema").
- Confirm the character's model format is solvable
- Verify animation contract rules are understood
- Check audio rules for the character

### Step 3: Prepare Candidate Only
```bash
# Extract BAG1 character assets
# Ensure these are available:
# - BAG1 model (DFS with TIMs, SEDT)
# - BAG1 animations (001.bin anim list)
# - BAG1 sound cues (SEDT bank)
# - Reference evidence from prior imports (Heat, etc.)
```

### Step 4: Record Reference Evidence
```bash
# audit_animation_roles.py is a legacy Heat adapter, not a generic character auditor.
# Use the shared contract/profile and the current character's verified references.

# Capture screenshots/video of:
# - Dance View animation roles
# - Fever modes (solo/duet)
# - Victory announcer
# - 2P autoplay behavior
```

### Step 5: Check Reference Evidence
- Compare BAG1 and BAG2 animation roles
- Verify fever dance mapping
- Check sound cue remapping (BAG1 → BAG2 bank remapping)
- Validate costume/version handling

### Step 6: Profile Schema Validation
- Ensure character JSON/profile follows the schema in CHARACTER_IMPORT.md
- Verify inventory rules (model slots, animation slots)
- Check animation contract rules are met

### Step 7: Animation Contract Rules
- Map BAG1 animation requests → BAG2 slots
- Verify fever type handling (0x8005E6C0 for solo, duet pads)
- Check beanie/accessory bone mappings
- Confirm dance grid compatibility

### Step 8: Audio Rules
- Remap BAG1 voice banks to BAG2
- Handle SEDT format conversion
- Preserve cue IDs where possible
- Rebase sound IDs if needed (0x1000 → 0x6000 offset)

### Step 9: Asset and Package Rules
- Rebuild DFS: `tools/bag1import/rebuild_dfs_members.py --spec <containers.json>`
- Create exact entries: `tools/bag1import/make_alt_entries_exact.py <disc.bin> <entries.json> <out>`
- Preserve every previously imported entry from its accepted payload; validate
  table bounds, DUMMY byte capacity and member hashes before deployment
- Follow `notes/character-alternate-entries.md`; `build_heat_test.sh` and the
  old sector-overlay `make_alt_entries.py` are legacy Heat adapters, not defaults
- Generate manifest overlay SHA256
- Synchronize task-owned sources/resources explicitly into the build tree;
  preflight reports drift but does not copy them
- Test in experimental install (BAG2JP-exp-8mb)

### Step 10: Acceptance Matrix
Verify criteria from CHARACTER_IMPORT.md section 10 ("Acceptance matrix") and
section 12 ("Evidence and context"):
- [ ] Model loads without crash
- [ ] Animations play correctly in Dance View
- [ ] Fever modes work (solo and duet)
- [ ] 2P autoplay behaves correctly
- [ ] Character select popup works with version/costume
- [ ] Victory announcer plays correctly
- [ ] No audio desync
- [ ] Mixed-version combat acceptance (if applicable)
- [ ] All four side/costume cases: P1/A, P1/B, P2/A, P2/B
- [ ] Full song and guarded return to selection (`-Finish`), with mods active
- [ ] Settings/state and original cards restored; logs/captures reviewed

### Step 11: Testing Discipline
- Run in-game verification in the experimental recompiled Windows runtime;
  use native BAG1/reference captures for comparisons, not as replacement acceptance
- Capture frame-perfect evidence for subjective judgments
- Test both BAG1 and BAG2 stages
- Verify online/netplay behavior if relevant

### Step 12: Evidence and Context
- Update `_work/current-state.json` with new status
- Add evidence to notes with `id`, `summary`, `related` fields
- Update `NOTES.md` index
- Generate digest if file changed significantly

## 3. Heat-Specific Adaptations (Example)

Based on the Heat import work completed (2026-10-29 to 2026-11-01):

### Model Format:
- BAG1 000+001 → BAG2 conversion via `tools/bag1import/model_bag1_to_bag2.py`
- Heat has 24 meshes + 14 type-4 nodes
- Converter tested and verified

### Animation Slots:
- BAG1 has 84 anims → mapped to BAG2 101 slots
- Fever type 0x8005E6C0 (1 solo, 2 duet) 
- Remapping done via `tools/bag1import/anim_remap.py`
- Key: BAG1 cue 0x1006 (step sound) → BAG2 Japanese voice

### Beanie/Floating Head:
- BAG1: head 12 + beanie 13
- BAG2: head 12 + extra chest bone 13
- Patch: `tools/bag1import/patch_heat_dbi.py` (sb v0,0xd → sb v0,0xc)

### Sound Handling:
- BAG1 bank 1 (005/007 cues 0x1000+) → voices + SE
- BAG2 bank 3 (006, p2 005) → announcer
- Only bank 1 swapped (BAG1 English 007)
- Cue IDs kept as is; effects 1-6 work

### 2P Autoplay:
- Mode 2 uses register hooks
- No CPU attacks in mode 2
- Verified: BAG1 Heat vs BAG1 Heat dancing with combos

### Victory Announcer:
- JP main-exe table 0x80051424, Heat cue 0x1007
- `preserve_announcer.py` merges stock name into VAB
- Opt-in for Heat in `build_heat_test.sh`

### Character Select Popup:
- Circle = costume A, Triangle + Circle = costume B
- Version selection: `bag2jp_bag1_set_version`
- Mirror rule: same character + costume → later pick gets costume ^ 1

## 6. When to Stop and Ask for Help

Stop and request guidance if:

1. Model format not solvable after 2+ hours of investigation
2. Animation roles cannot be mapped (missing BAG1 → BAG2 equivalents)
3. Sound remapping causes desync or crashes
4. 2P autoplay behavior unexpected after 3 test runs
5. Victory announcer cannot be preserved
6. Character select popup logic unclear

**In these cases:** Create a new note documenting the gap, add to `_work/current-state.json` as a "pending exception", and wait for owner review.
